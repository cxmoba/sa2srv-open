## item.bin — 物品总表 (XOR 0xFF, 0x128 字节/条, 8729 条; 字符串 UTF-16LE)
| 偏移 | 含义 |
|---|---|
| +0 u16 | 物品号 |
| +2 wchar[0x19] | 名字 |
| +0x34 u16 | 背包页/装备位 (= 我们 items.txt 的 loc: 1 头 2 身 3 斧 4/5 枪… 0x13 食物 0x14 素材 0x15 其他) |
| +0x36 u16 | 小类 (0x21 斧, 0x41 枪, 0xb4 肉, 0xcb 果…) |
| +0x38 u16 | ? (多为 1) |
| +0x3a 5×{u16,u16} | 需求/限制? (0x53 = 空) 未确认 |
| +0x50 u16, +0x54 i32 | 主效果: 11 攻击 / 12 防御 / 4 回体力 (+值), 83 = 无 |
| +0x58 7×{u16 0, u16 属性码, i32 值} | 附加属性: 0x43 致命, 0x42 反击, 0x0d/0x0e/0x58/0x59/0x88/0x27 … (0x27 疑似气力) 未全对 |
| +0x94 u16, +0x96 u16 | ? |
| +0x98 wchar[0x41] | 说明 |
| +0x11a u16 | 图标 (CG 号) |
| +0x11c u32 | 价格 |
| +0x120 i32, +0x124 i32 | ? (+0x124 多为 1, 任务物品 40003 为 0 → 可能"可卖/可交易") |


## mapdata/*.bin — 地图 (明文)
- 头 40 字节: "MAP\0", u32 分段起点, u16 版本 0x105, u16 地图号, u16 宽, u16 高, u32 时间戳, u16 区域号 (战斗背景/遇敌区, 如 201, 100), 其余未明。
- 40 起 (w/2)×(h/2) 个 u32 地砖 (w,h 是子格数, 一块地砖 = 2×2 子格): 高 16 位 = 地砖号 (查 map/chipinfo.bin), 低 4 位 = 换图标记 (每位一个子格; 带标记的子格与 JUMP 出口格一一对应)。
- 分段: 4 字节 tag + u32 段长 (含 8 字节头) + u16 版本 0x105 + u32 条数 + 条目:
  - **JUMP** 8 字节 {u16 x, u16 y, u16 目标地图, u16 目标落点号}: 出入口格。目标图 = 本图时是图内跳 (790 格)。
  - **JUM2** 11 字节 {u16 落点号, u16 x, u16 y, u32 ?, u8 朝向}: 本图落点。
  - **EVEN** 8 字节 {u16 x, u16 y, u16 值, u16 ?}: 事件格 (00003: (552,237)→16000) 未确认。
  - OBJ1 物件, DINO (很大, 疑似每格数据), BATT (疑似遇敌区), PLAC, LAYE: 未解。
- 验证: 10006 西口 (1,16..21) → 100; 10006 落点 1 = (2,17) ≈ 我们 warp.txt 落点 (3,17)。地图 1 的落点 1/20..23 = (229,874)/(295..304,797) ≈ warp.txt 的 (230,877)/(297,797)。地图 1 西边 (99,842) → 地图 2 落点 110 (1649,1042)。
- 结果: 151 张图有 JUMP/JUM2; 404 组出口, 150 组能在目标图找到落点 (map_warps_resolved.csv)。**哈鲁保村 100 和很多城镇图没有 JUMP/JUM2** (只有 OBJ1/PLAC/LAYE), 所以进村方向的落点还得靠 pth/pthinfo。

## event_w.bin — 任务表 (不是传送表)
- 客户端读取: 0x4f85c0 (类 vtable 0x6793a4) 用通用读文件 0x423740 读入, 0x4236d0(0xff) 整个文件逐字节异或 0xFF;
  记录数 = 文件长 / 0x6f0 (0x27350b89 乘法除以 1776)。取字段的小函数在 0x4f8820..0x4f8dcc (都是 `imul 0x6f0`)。
- 1703184 字节 = 959 条 × 0x6f0 (1776)。717 个不同任务 id (最大 807); 同 id 多条 = 同一任务的几个阶段/分支。
- 字符串都是 UTF-16LE, 以 0 结尾, 后面的空位是 0xFF 填充 (所以原文件里看到大片 00)。

| 偏移 | 类型 | 含义 | 依据 |
|---|---|---|---|
| +0x000 | i32 | 任务 id | 1,2,3… |
| +0x004 | wchar[0x80] | 任务名 "第一次的试练" | 访问器 0x4f8880 |
| +0x104 | i32 | 委托 NPC 图号 (58xxx NPC 图 / 20xxx 人物图) | 同名 NPC 基本同值; 访问器 0x4f8910 |
| +0x108 | wchar[0x82] | 委托 NPC 名 "哈鲁保的长老" | 0x4f88e0 |
| +0x20c, +0x210 | i32, i32 | NPC 坐标 x, y (长老 140,77) — 不带地图号 | 0x4f8940/0x4f8970 |
| +0x214 | wchar[0x80] | 委托台词 | 0x4f88b0 |
| +0x314 | wchar[0x80] | 任务目标说明 | 0x4f89d0 |
| +0x414 | i32 | 条件变量号 (10001, 10124, 5020 …) | 0x4f8720 比较 |
| +0x418 | wchar[4] | 比较符 "==" / "!=" | 0x4f8720 比较 0x3d / 0x21 |
| +0x420 | i32 | 条件值 | 同上 |
| +0x424 / +0x428 / +0x430 | i32 / wchar[4] / i32 | 第二条件 (大多空, 13 条 "==", 1 条 "~=") | 未确认 |
| +0x434 … +0x490 | 8×{i32,i32,i32} | 需求: 物品号, 数量, ? (任务1: 20042 克克尔的肉 ×3; 任务2: 40003 破烂的钟 ×1; 任务3: 20520 新鲜活鱼 ×1) | 文本对照; 第三个值偶尔是 47902 之类 (怪物号?) 未确认 |
| +0x494, +0x498 | i32 | ? (3 条有 1441, 6000) | |
| +0x49c, +0x4a0, +0x4a4 | i32 | ? (常见 1,100,100 / 3,…) | 访问器 0x4f8820/0x4f8850/0x4f89a0 |
| +0x4a8 … +0x4e4 | 16×i32 | 奖励块? 468 条整块 -1 (无); 其余像 {物品号, 数量} 对 (+0x4c8/+0x4cc, +0x4d0/+0x4d4, +0x4d8/+0x4dc) 和数值 (+0x4c0, +0x4c4 像经验/石币) | 未确认 |
| +0x4e8 | wchar[0x80] | 备注 "开始NPC：精灵使" | |
| +0x5ec | wchar[0x80] | 备注 "结束NPC：精灵使" | |
| +0x6ec | i32 | ? (126 条非 0, 如 628/511) | |

**结论: 没有地图号/传送目标, 不能用来生成 warp.txt。** 传送仍以 pth/pthinfo/link 为准。

## mapposlist.bin — 世界地图上的区域/城镇位置
- 客户端读取: 0x4c0f30, 明文 (不加密)。头 16 字节: "MAPL", u32 文件长 (0x28c), u32 0x100 (版本?), u32 条数 53。
- 每条 12 字节 = 6×u16: `id, parent, x, y, w, h`。读入后 x,y 向下取偶数, w,h 向上取偶数, 按 id 存进 std::map (0x7186dc), 再按 parent 链接。
- id 1..50 = 区域 (parent 2 = 马加岛整图 0,0,2970,2010; 11..14 属于 13, 31..37 属于 31 …); id 100..470 = 城镇/地点标记 (100 = 哈鲁保村, 在区域 2 图上 1730,950, 150×150)。坐标是世界地图图片上的像素。
- 只有 53 条, 不含洞窟/室内图 (10006 等), 也没有出入口格 → **不是传送表**, 只用于世界地图 UI 定位。
